# 学习路线

> 从「看得懂代码」到「能让一块板子按你的想法动起来」。四个阶段按依赖关系排列，每个阶段都配一个能拿出手的小作品。

嵌入式开发和纯软件最大的区别，是你要同时对三样东西负责：**代码、电路、时间**。代码要跑在只有几十 KB 内存的芯片上，电路决定了电平长什么样，而时间——中断在什么时候抢进来、任务多久切一次——往往才是 bug 的来源。所以这条路线刻意把「软件」和「硬件」交替安排：先有 C 的底子，再看懂电路，然后才上单片机，最后用 RTOS 处理多任务的复杂度。

## 路线总览

| 阶段 | 主题 | 参考周期 | 阶段产出 |
| --- | --- | --- | --- |
| 一 | C 语言基础 | 4 ~ 6 周 | 独立写出带指针、结构体和位运算的控制台程序 |
| 二 | 数字电路 | 4 ~ 6 周 | 看懂开发板原理图，会分析简单时序 |
| 三 | 单片机（STM32 / 51） | 8 ~ 12 周 | 用 GPIO、中断、定时器、串口、I2C 做出一个小项目 |
| 四 | RTOS（FreeRTOS） | 6 ~ 8 周 | 把裸机项目改写成多任务 + 队列的结构 |
| 进阶 | 通信 / Linux / 边缘 AI | 持续 | 选定一个方向深入做下去 |

::: tip 关于「参考周期」
周期按每周投入 6 ~ 10 小时估算。有人快有人慢，**判断标准不是学了几周，而是能不能通过每个阶段末尾的「自查标准」**。如果某一阶段的自查标准过不了，先别急着往下走——后面所有内容都建立在前一阶段之上。
:::

## 第 0 周：先把工具装上

在写第一行代码之前，先把环境装好。这一步劝退的新手比 C 语言本身还多，建议照着表逐个装，装完再往下看。

| 工具 | 作用 | 备注 |
| --- | --- | --- |
| Keil MDK 5 | 编译、下载、调试 | 资料最多、学校常用；社区版有代码大小限制 |
| STM32CubeMX | 图形化配置时钟和外设，生成初始化代码 | 配合 HAL 库使用 |
| ST-Link 驱动 | 下载程序、单步调试 | 插上能在设备管理器识别才算装好 |
| 串口驱动 | USB 转串口的 CH340 / CP2102 芯片 | 设备管理器里出现 COM 口才行 |
| PlatformIO + VS Code | 另一套工具链，跨平台、命令行友好 | 不想装 Keil 可以选这条路线 |

装完做一件事验收：**新建工程 → 点亮一个 LED**。这一步跑通，说明编译链、下载器、板子和驱动全都正常，之后的 C 和外设学习才有意义。

> 装不上不用硬扛，把「报什么错 + 截图」发到群里，比一个人折腾一下午快得多。

## 阶段一：C 语言基础

嵌入式的 C 和课堂上的 C 不完全一样：没有 `printf` 随手可用，栈只有几 KB，动态内存要慎用，还要频繁和寄存器、位域打交道。

### 学什么

按优先级从高到低：

1. **数据类型与内存布局**：`char / short / int / long` 到底占几个字节，`sizeof` 为什么重要，栈和堆的区别。
2. **指针**：指针与地址、指针运算、指针与数组的关系、函数指针（后面写回调全靠它）。
3. **结构体与联合体**：`struct` 的内存对齐、`union` 的用法（解析通信帧时很常用）。
4. **位运算**：`& | ^ ~ << >>`，置位、清位、取某一位、判断某一位——这是操作寄存器的基本功。
5. **关键字的真实含义**：`static`、`const`、`volatile`、`extern` 各自解决什么问题，尤其是 `volatile`（中断里改的变量不加它，编译器优化会让你怀疑人生）。
6. **预处理器**：`#define`、条件编译、头文件保护。

位运算不用背，但下面四个宏建议直接抄进自己的头文件，以后天天用：

```c
#define BIT(n)         (1U << (n))
#define SET_BIT(r, n)  ((r) |=  BIT(n))
#define CLR_BIT(r, n)  ((r) &= ~BIT(n))
#define GET_BIT(r, n)  (((r) >> (n)) & 1U)
```

例如把 `GPIOA` 的第 5 位置 1、把第 3 位清 0：

```c
SET_BIT(GPIOA->ODR, 5);
CLR_BIT(GPIOA->ODR, 3);
```

### 怎么学

- **不要一开始就啃完 800 页的书**。先跟着视频把语法过一遍，然后立刻用项目把知识「用出来」。
- 每学一个知识点，就在电脑上写一个 20 行以内的小程序验证它，尤其是指针和位运算——**看会和写对是两件事**。
- 养成看警告的习惯：`-Wall -Wextra` 全开，警告当错误看。
- 用调试器单步走一遍指针赋值，盯着变量地址怎么变，比看十遍讲解都直观。

### 资源建议

| 资源 | 说明 |
| --- | --- |
| 《C Primer Plus》第 6 版 · 书 | 系统全面，例子多，适合零基础通读一遍 |
| 《C 和指针》（Kenneth Reek）· 书 | 指针薄弱时专项补，讲得比大多数教材清楚 |
| 翁恺《C 语言程序设计》· 视频 | 浙江大学开设，中国大学 MOOC、B 站可看，中文入门课里讲得最细的一档 |
| CS50 · 视频 | 哈佛大学 edX 课程，英文过关的话，计算机思维训练比语法训练更值钱 |
| LeetCode 简单题 · 练习 | 只做数组、字符串、链表部分，练手感和边界条件 |

### 自查标准

- 能手写 `strlen`、`memcpy`、`strcpy`，并说清边界情况怎么处理。
- 能解释 `int *p[10]` 和 `int (*p)[10]` 的区别。
- 能说清 `a[i]` 为什么等价于 `*(a + i)`。
- 能用一行位运算把寄存器的第 3 位置 1、第 5 位清 0。
- 能说清 `volatile` 在中断场景下不加会出什么问题。

## 阶段二：数字电路

这一阶段的目标不是考试做题，而是**拿到一张原理图，能看懂每个器件在干什么、信号从哪来到哪去**。

### 学什么

1. **数制与编码**：二进制、十六进制、BCD、补码（理解负数在芯片里怎么存）。
2. **逻辑门与布尔代数**：与或非、异或，真值表、卡诺图化简（知道方法即可，实际靠工具）。
3. **组合逻辑**：译码器、编码器、多路选择器、加法器、比较器。
4. **时序逻辑**：RS / D / JK 触发器、寄存器、计数器、移位寄存器。
5. **时钟与复位**：上升沿触发、同步与异步复位、时钟抖动。
6. **时序分析**：建立时间（setup）、保持时间（hold）、传播延迟——为什么信号太快会「错拍」。
7. **电气常识**：TTL / CMOS 电平、3.3V 与 5V 互连、上拉电阻与下拉电阻、开漏输出、去抖。

### 怎么学

- 把「电路 ↔ 真值表 ↔ 时序图」三者当成同一件事的三种写法，反复互相转换，这是数电的核心能力。
- 用仿真软件先把电路跑起来，再去看实物：改一个输入，观察输出怎么变，比背公式有效得多。
- 学完组合逻辑和时序逻辑后，**立刻去读一块真实开发板的原理图**（比如 STM32 最小系统板），试着指出电源、复位、晶振、LED、按键分别怎么接。

### 资源建议

| 资源 | 说明 |
| --- | --- |
| 阎石《数字电子技术基础》· 书 | 清华大学出版社，国内最通用的教材，体系完整 |
| 康华光《电子技术基础·数字部分》· 书 | 另一个常见版本，讲解角度略有不同，可作参考 |
| 清华大学《数字电子技术基础》公开课 · 视频 | B 站可看，配合教材看，推导过程更清楚 |
| Digital（hneemann/Digital）· 工具 | 免费的逻辑电路仿真，画完直接看时序 |
| 立创 EDA · 工具 | 国产原理图 / PCB 工具，和后面画板子衔接 |

### 自查标准

- 能用逻辑门搭出 3-8 译码器，并说明为什么需要使能端。
- 能画出 D 触发器的时序图，说清「上升沿采样」是什么意思。
- 能指出开发板原理图上 LED 是灌电流还是拉电流接法，限流电阻大概多大。
- 能解释按键为什么要加上拉电阻和去抖。
- 看到 I2C 的时序图，能说出起始条件、应答位分别长什么样。

## 阶段三：单片机

这是真正开始「写代码让硬件动」的阶段。选型上建议直接上 **STM32**（生态和资料最厚），如果手头只有 51 开发板，用它入门也完全可以，只是外设会少一些。

### 学什么

按外设依赖顺序推进，一步一个脚印：

| 顺序 | 外设 | 要解决的问题 |
| --- | --- | --- |
| 1 | GPIO | 点灯、按键、输入输出模式（推挽 / 开漏 / 上拉） |
| 2 | 时钟树 | 系统时钟从哪来，为什么外设要单独使能时钟 |
| 3 | 中断与 NVIC | 中断优先级、中断服务函数该写多短 |
| 4 | 定时器 / PWM | 定时、计数、呼吸灯、电机调速 |
| 5 | 串口 USART | 和电脑通信、环形缓冲区收不定长数据 |
| 6 | ADC | 采集电压、采样时间与分辨率 |
| 7 | I2C / SPI | 驱动 OLED、温湿度、Flash 等外设 |
| 8 | DMA | 让数据搬运不占 CPU |
| 9 | 看门狗 / 低功耗 | 产品化必须考虑的两件事 |

### 怎么学

- **先建工程再点灯，不要直接改例程**。从零新建一次工程、配置一次时钟、写一次寄存器，比改十次例程学到的多。
- 每学一个外设，都问自己三个问题：它靠什么触发？数据从哪来、到哪去？出错时现象是什么？
- 备一个几十块的**逻辑分析仪**，串口、I2C、SPI 的波形直接看，比猜快得多。
- 调试优先用 `ST-Link` 单步 + 变量观察，而不是靠大量 `printf` 打日志。

### 资源建议

| 资源 | 说明 |
| --- | --- |
| 江协科技（江科大自化协）STM32 入门教程 · 视频 | B 站，中文 STM32 入门课里口碑最好的一档，标准库和 HAL 都有 |
| 野火、正点原子的教程与例程 · 资料 | 例程全、配套板子多，适合当字典查 |
| ST 官方《STM32 参考手册》（RM0008 等）与数据手册 · 文档 | 最终以它为准，学会查寄存器和电气参数 |
| 《ARM Cortex-M3 权威指南》（Joseph Yiu 著，宋岩 等译）· 书 | 想搞懂中断、异常、启动流程时读 |
| STM32CubeMX + HAL、PlatformIO + VS Code · 工具 | CubeMX 生成初始化代码；PlatformIO 跨平台、命令行友好 |

### 建议的小项目

按难度递增，做完一个再下一个：

1. 按键控制 LED，加消抖（软件延时 → 定时器 → 状态机，三种写法都写一遍）。
2. 串口命令行：电脑发指令，板子回数据，支持参数解析。
3. 定时器 PWM 调光 + 编码器测速，做一个闭环调速。
4. I2C 驱动 OLED，显示温湿度传感器读数。
5. 综合项目：**数据采集盒**（多路 ADC + 串口上传 + 按键菜单）或**循迹小车**。

### 自查标准

- 不看教程，能从空文件夹新建一个工程并点亮 LED。
- 能说清中断服务函数里为什么不能写 `delay`。
- 能用「中断 + 环形缓冲区」接收不定长串口数据，不丢包。
- 能独立用逻辑分析仪抓一次 I2C 通信并解析出地址和数据。
- 遇到板子不工作时，有清晰的排查顺序（供电 → 时钟 → 复位 → 引脚复用 → 代码）。

## 阶段四：RTOS

当项目里同时有按键、显示、通信、控制，裸机的 `while(1)` 加状态机会迅速变成一堆互相纠缠的 `if`。RTOS 解决的就是「多个任务怎么有条不紊地分享一颗 CPU」。

### 学什么

- **任务与调度**：任务状态、优先级、抢占式调度、时间片。
- **上下文切换**：为什么切换有开销，栈要开多大。
- **同步与通信**：信号量、互斥量、队列、事件组、任务通知，以及它们各自适合什么场景。
- **临界区与优先级反转**：关中断、`taskENTER_CRITICAL`，互斥量为什么能缓解优先级反转。
- **软件定时器、内存管理、栈溢出检测、看门狗配合**。

### 怎么学

- 先理解**为什么要用**，再学 API。用一个具体场景（比如「按键 + 屏幕刷新 + 串口上报」）去对照裸机写法和 RTOS 写法的差别。
- 一定要做实验：故意制造优先级反转、故意让任务栈溢出、故意在中断里用非 `FromISR` 版本，然后观察现象。
- 最后把阶段三的综合项目**重写一遍**成多任务结构，这一步的收获远大于看视频。

### 资源建议

| 资源 | 说明 |
| --- | --- |
| 《Mastering the FreeRTOS Real Time Kernel》· 书 | FreeRTOS 官方免费 PDF，讲原理最清楚的一本，配合 freertos.org 的 API 文档看 |
| 正点原子《FreeRTOS 开发指南》、野火 RTOS 教程 · 资料 | 中文、贴 STM32，适合先跑通再回头读原理 |
| RT-Thread 官方文档 · 文档 | 国产 RTOS，组件生态完整，可以当第二个 RTOS 对照学 |
| FreeRTOS 官方源码与例程 · 代码 | 例程短小，适合逐个改参数观察行为 |

### 自查标准

- 能说清中断里为什么要用 `xQueueSendFromISR` 而不是 `xQueueSend`。
- 能解释「任务饿死」和「优先级反转」分别是怎么发生的。
- 能给每个任务估算并实测栈使用量。
- 能用队列 + 信号量把「采集任务 → 处理任务 → 通信任务」串起来，且不阻塞。

## 进阶方向（选一个深入）

学完上面四个阶段，你已经能做完整的嵌入式小项目了。接下来按兴趣选一条路，**选一条走深，比每条都浅尝更值钱**。

| 方向 | 内容 | 入门抓手 |
| --- | --- | --- |
| 通信与协议 | CAN、Modbus、BLE、LoRa、MQTT | 用两块板子互发数据，抓包分析帧结构 |
| 嵌入式 Linux | 内核裁剪、设备树、字符设备驱动 | 买一块 Linux 开发板，从点灯驱动写起 |
| 边缘 AI | TFLite Micro、CMSIS-NN、模型量化与部署 | 在 MCU 上跑一个关键词识别或手势识别 |
| 硬件设计 | 原理图、PCB、打样、焊接调试 | 用立创 EDA 画一块自己的最小系统板并打样 |

## 时间怎么安排

- **每周固定 6 ~ 10 小时**，比周末突击一整天有效。建议 2 小时看资料、4 小时写代码、2 小时调 bug。
- **每个阶段结束留一个「作品」**：能演示、有 README、有一张接线图。作品攒在 [项目展示](/projects) 里，面试和组队都用得上。
- **卡住超过 2 小时就去问人**：在协会群里贴出「现象 + 代码片段 + 接线照片」，比一句「不亮」得到的帮助多十倍。
- **写学习笔记**：把踩过的坑记下来，三个月后你会感谢自己。

## 常见问题

**要不要先学 51 再学 STM32？**
不必。51 的价值在于「寄存器少、看得清底层」，如果你已经有 51 板子，花两三周点灯、跑串口再转 STM32 也不错；没有的话直接从 STM32 开始，效率更高。

**数学和英语不好能学吗？**
能。日常开发用到的数学是位运算、简单换算和一点三角函数；英语主要是读数据手册，术语见多了自然就熟。真正的门槛是耐心，不是天赋。

**第一块板子买什么？**
STM32F103C8T6 最小系统板 + ST-Link 下载器，成本一百块以内，资料最全。再配一个逻辑分析仪和一块面包板，够用到阶段四。

**视频看完了还是不会写怎么办？**
因为「看」是被动输入。把视频关掉，只留一个需求（比如「按键长按 2 秒后 LED 慢闪」），从空工程开始写。写不出来再回去查对应章节，这样一次顶三次。

**一定要参加比赛吗？**
不是必须，但比赛能给你一个「必须做完」的截止时间和一群一起熬夜的队友，这两样东西对新手特别有用。可以在 [活动公告](/events) 里留意组队信息。
